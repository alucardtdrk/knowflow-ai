# KnowFlow AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar uma aplicação de portfólio executável localmente, com equipes, consulta documental verificável, orientação guiada e solicitações internas.

**Architecture:** Aplicação Next.js integrada com PostgreSQL/pgvector e arquivos privados em armazenamento S3. Um trabalhador do mesmo projeto processa documentos com fila persistida no PostgreSQL. Dados de demonstração são fictícios e identificados; a integração real exige credenciais configuradas.

**Tech Stack:** TypeScript, Next.js App Router, PostgreSQL/pgvector, Drizzle para schema/migrações, Better Auth para autenticação, SDK OpenAI no servidor, SDK S3, Zod, Vitest e Playwright. Confirmar compatibilidade e APIs nas documentações oficiais durante execução, fixar versões no lockfile. Docker Compose para PostgreSQL e armazenamento S3 local; fila com tabela própria e claim transacional, sem novo serviço de dados.

**Spec:** ../specs/2026-11-05-knowflow-design.md (aprovada, incluindo adendo de portfólio).

## Global Constraints

- Interface em português e uso responsivo.
- Formatos iniciais: PDF com texto, DOCX e TXT.
- Limite de 20 MB por arquivo.
- Organização e equipe são verificadas no servidor em toda operação de conteúdo.
- Conversas são privadas ao autor; solicitações incluem apenas o resumo confirmado.
- Primeira versão sem OCR, cobrança, integrações externas, compartilhamento público ou busca entre equipes.
- Sem documentação suficiente, reconhecer a lacuna; nunca inventar fontes.
- Arquivos e credenciais privados. Conteúdo documental e mensagens são dados não confiáveis.
- Projeto de portfólio: dados fictícios, inicialização reproduzível, demonstração rotulada e README completo. Não publicar automaticamente.

## Review Focus

- Remoção de membro durante conversa ou trabalho pendente deve revogar acesso; testar nas tarefas 1 e 2.
- PDF sem texto, arquivo disfarçado e upload interrompido devem falhar com recuperação; testar tarefa 2.
- Exclusão concorrente ao processamento não pode ressuscitar documento; testar tarefa 2.
- Modelo retornando fonte inexistente ou instrução maliciosa deve resultar em resposta segura; testar tarefa 3.
- Clique duplicado ou resultado de passo desatualizado não pode criar solicitações duplicadas ou corromper sequência; testar tarefa 4.

## Arquivos e contratos compartilhados

- `src/app/`: páginas, layouts, server actions e rotas HTTP; toda mutação valida entrada e sessão.
- `src/components/`: componentes visuais compartilhados somente quando reutilizados.
- `src/lib/db/schema.ts`, `src/lib/db/index.ts`, `drizzle/`: entidades, conexão e migrações.
- `src/lib/auth.ts`, `src/lib/access.ts`: autenticação e autorização.
- `src/features/documents/{service,storage,extract,worker}.ts`: ingestão e documentos.
- `src/features/assistant/{service,retrieve,provider}.ts`: busca, contexto e geração.
- `src/features/requests/service.ts`: passos guiados e encaminhamento.
- `scripts/{worker,seed}.ts`, `fixtures/`: execução e exemplos fictícios.
- `tests/{access,documents,assistant,requests}.test.ts`, `e2e/knowflow.spec.ts`: verificações de comportamento.
- `public/brand/`, `src/app/globals.css`: SVGs e identidade v3.
- `compose.yaml`, `.env.example`, `.gitignore`, `package.json`, `README.md`, `.github/workflows/ci.yml`: execução, configuração e documentação.

Tipos comuns: `Actor = { userId: string }`; `Scope = { organizationId: string; teamId: string }`; `Source = { chunkId: string; documentId: string; title: string; location: string; excerpt: string }`. IDs são UUIDs. Actor vem exclusivamente de sessão validada, nunca do corpo da requisição. Escopo é validado em cada serviço; não confiar em escopo autorizado por chamada anterior.

## Task 1: Organização, equipes e experiência navegável

**Files:** criar configuração raiz, schema e migrações, auth/access, layout e páginas de entrada, organização/equipe/configurações, componentes compartilhados, marca e `tests/access.test.ts`.

**Interfaces:** produzir `requireActor(): Promise<Actor>` e `requireTeamAccess(actor: Actor, scope: Scope, role?: 'manager'): Promise<void>`. Administrador organizacional não implica membro da equipe. Schema inclui usuários/sessões conforme biblioteca, organizações, memberships, equipes, convites e auditoria. Ações de gestão usam o papel correspondente.

- [ ] Confirmar APIs oficiais e ambiente Node/npm/Docker; criar scripts `dev`, `build`, `lint`, `typecheck`, `test`, `test:integration`, `test:e2e`, `db:migrate`, `db:seed`, `worker`. Configurar testes de integração contra banco descartável identificado explicitamente, nunca banco de uso.
- [ ] Escrever testes: `rejectsOtherOrganization`, `rejectsNonMemberAdmin`, `revokesRemovedMember`, `acceptsInvitationOnceForMatchingEmail`; assertar recusa para usuário errado, convite expirado e reutilização.
- [ ] Executar `npm run test:integration -- tests/access.test.ts` e observar falha por implementação ausente.
- [ ] Implementar banco, autenticação por email/senha usando biblioteca, convites por link copiado (sem email externo), gestão de equipe e guards. Guardar tokens de convite com hash; auditar mudanças de acesso. Validar env no servidor sem imprimir segredos.
- [ ] Implementar navegação responsiva, seleção explícita de contexto, formulários acessíveis e identidade v3. Copiar SVGs do brand kit; não usar mockup como tela. Aplicar paleta v3 sem azul residual ou gradientes conflitantes.
- [ ] Verificar testes de acesso, `npm run typecheck`, `npm run lint` e `npm run build`; conferir navegação e estados vazios.

## Task 2: Documentos reais e ingestão em segundo plano

**Files:** documentos service/storage/extract/worker, `scripts/worker.ts`, páginas e rotas de documentos e fontes, schema/migrações adicionais, fixtures PDF/DOCX/TXT, `tests/documents.test.ts`, compose/env.

**Interfaces:** consumir Actor/Scope e guards. Produzir `uploadDocument(actor: Actor, scope: Scope, file: File): Promise<{ id: string }>`; `deleteDocument(actor: Actor, scope: Scope, id: string): Promise<void>`; `getSource(actor: Actor, scope: Scope, chunkId: string): Promise<Source>`; `processNextJob(): Promise<boolean>`. Só gestor altera documentos; membro lê. Jobs guardam escopo persistido e verificam documento ativo antes de cada commit.

- [ ] Escrever testes `rejectsOversizeAndDisguisedFiles` (20 MB permitidos, acima recusado), `rejectsScannedPdf`, `preservesPdfPageAndTextLocation`, `retriesFailedJob`, `doesNotResurrectDeletedDocument`, `blocksUnauthorizedDownload`, `cleansInterruptedUpload` e `revokesSourceAfterRemoval`.
- [ ] Rodar `npm run test:integration -- tests/documents.test.ts`; confirmar falhas específicas antes de implementar.
- [ ] Implementar upload validado, arquivos privados, extração com bibliotecas de PDF/DOCX, limites também de texto extraído para não esgotar memória, chunks com localização e embeddings. Tabela de jobs com lock, lease recuperável e máximo de três tentativas; processamento idempotente. Escrever chunks em transação, tornar pesquisável apenas documento pronto. Exclusão marca indisponível antes de limpar objetos e derivados; worker verifica tombstone.
- [ ] Implementar lista com status, repetição explícita após falha, exclusão, download e referência autorizados. Explicar PDF sem texto e fonte excluída. Downloads não usam URL pública duradoura.
- [ ] Rodar testes de documentos, acesso e verificação de tipos; iniciar Compose, enviar cada fixture e conferir status/localização. Confirmar mensagem útil quando credencial de embeddings está ausente.

## Task 3: Perguntas com fontes e orientação persistida

**Files:** assistant service/retrieve/provider, schema de conversas/mensagens/passos, página de conversa, `tests/assistant.test.ts`.

**Interfaces:** `retrieve(actor: Actor, scope: Scope, query: string): Promise<Source[]>`; `answer(actor: Actor, scope: Scope, input: { conversationId?: string; message: string }): Promise<{ conversationId: string; text: string; sources: Source[]; stepId?: string }>`; `recordStepResult(actor: Actor, scope: Scope, input: { stepId: string; result: 'worked' | 'failed' | 'unable' }): Promise<void>`. Saída do modelo validada com schema; citações só podem apontar trechos recuperados. Provedor consome trechos e mensagem, sem ferramentas de execução.

- [ ] Escrever testes `citesOnlyRetrievedChunks`, `admitsMissingEvidence`, `doesNotFollowDocumentInstructions`, `keepsConversationPrivate`, `persistsGuidedStep`, `rejectsStaleStepResult`, `handlesProviderTimeout`, `rejectsOverLimitRequests`; verificar também consulta fora de escopo e indisponibilidade sem duplicar mensagens.
- [ ] Rodar `npm test -- tests/assistant.test.ts` com provedor substituído por fixture de teste; observar falhas.
- [ ] Implementar busca vetorial filtrada por escopo e documentos prontos, geração estruturada, checagem de referências e fallback quando não há evidência. Limitar pergunta a 4.000 caracteres, geração a 2.000 tokens e timeout a 45 segundos; limite inicial de 10 gerações/minuto por usuário persistido no banco. Não usar similaridade como promessa de confiança.
- [ ] Implementar conversas privadas com resposta direta ou passo guiado, confirmação de resultado e fontes conferíveis. Validar propriedade em leitura/escrita e revogar ao sair da equipe. Renderizar texto/Markdown sem HTML arbitrário, links seguros e sem conteúdo bruto nos logs.
- [ ] Rodar testes unitários e de integração relevantes; conferir manualmente uma pergunta conhecida e outra não respondida pela fixture usando integração real se houver credenciais. Registrar ausência de teste real se não houver.

## Task 4: Encaminhamento e solicitações

**Files:** requests/service, schema/migrações, páginas de solicitações, formulário de resumo no assistente, `tests/requests.test.ts`.

**Interfaces:** `createRequest(actor: Actor, scope: Scope, input: { confirmationId: string; title: string; summary: string; conversationId?: string }): Promise<{ id: string }>`; `updateRequest(actor: Actor, scope: Scope, input: { id: string; status?: 'open' | 'in_progress' | 'resolved' | 'closed'; assigneeId?: string | null; comment?: string }): Promise<void>`. ConfirmationId único por autor para idempotência. Resumo é editável e confirmado; conversa completa não fica acessível ao gestor.

- [ ] Escrever testes `requiresExplicitConfirmation`, `deduplicatesConfirmation`, `sharesOnlyApprovedSummary`, `restrictsMemberToOwnRequests`, `assignsOnlyTeamManagers`, `allowsAuthorToReopen`, `reservesClosureForAuthor` e `blocksAccessAfterMembershipRemoval`.
- [ ] Rodar `npm run test:integration -- tests/requests.test.ts` e confirmar falhas.
- [ ] Implementar resumo editável com testes/resultados/fontes selecionados, confirmação e criação idempotente. Lista do gestor mostra equipe; membro vê próprias solicitações. Aplicar transições explícitas: gestor aberta/em atendimento/resolvida; autor encerra/reabre, sem fechar solicitações alheias.
- [ ] Implementar detalhes, comentários, atribuição e estados vazios/erro. Conferir que fonte excluída é indicada como indisponível, sem expor trecho excluído por endpoint.
- [ ] Rodar testes de solicitações e regressões de acesso/assistente.

**Interfaces:** seed cria duas organizações e duas equipes, usuários fictícios com papéis diferentes, documentos e solicitações. Só executar seed em ambiente local explicitamente habilitado. Demonstração sem IA usa conversas pré-carregadas rotuladas como exemplo; não simula busca livre ou processamento bem-sucedido. Produção sem chave exibe indisponibilidade explicada, nunca resposta fictícia disfarçada.

- [ ] Escrever teste E2E com sessão autenticada: selecionar equipe, enviar TXT, aguardar ingestão com provedor fixture apenas no ambiente de teste, perguntar, abrir fonte, registrar resultado de passo, confirmar solicitação, acompanhar como gestor. Adicionar cenário de usuário de outra organização recusado e navegação móvel por teclado.
- [ ] Executar `npm run test:e2e`; confirmar falhas dos elementos ainda ausentes.
- [ ] Implementar seed idempotente com nomes/conteúdo fictícios, exemplos em RH e TI para demonstrar flexibilidade e caminho local sem chave claramente rotulado. Sem desvio de autenticação na aplicação publicada; fixtures de provedor de teste não podem ser habilitadas em produção.
- [ ] Escrever README com problema, funcionalidades reais, capturas da aplicação, arquitetura, decisões e limites; comandos de instalação, Docker, migrações, seed, worker e app; variáveis, testes e funcionamento sem credenciais. Incluir aviso de processamento externo e limite de retenção do histórico após excluir fonte. Não declarar licença sem escolha do autor.
- [ ] Configurar CI de instalação pelo lockfile, lint, tipos, testes e build com serviços de teste; nenhuma chave real no repo. Conferir arquivos ignorados e ausência de segredos antes de qualquer commit.
- [ ] Rodar `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:integration`, `npm run test:e2e`, `npm run build`; conferir visual em desktop e celular, iniciar seguindo o README e registrar bloqueios de ambiente sem declarar testes não executados como aprovados.

As cinco entregas foram implementadas. Verificação final: lint sem avisos, tipos e build aprovados; 16 testes unitários, 16 de integração, seis testes de demonstração (desktop/celular) e um percurso autenticado completo passaram (39 ao todo). Adaptações de ambiente: sem Docker disponível, testes de banco usam PGlite/pgvector. Não valida infraestrutura Docker, fornecedores reais ou qualidade semântica de um modelo real. Seed local fornecido, sem execução contra serviços Docker neste ambiente.

Repositório iniciado localmente na branch feat/knowflow; nenhuma publicação no GitHub ou contratação de serviço faz parte da entrega. As caixas originais preservam a redação planejada; etapas dependentes de Docker/credenciais reais não são declaradas executadas.
